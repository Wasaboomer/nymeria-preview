# Mago / Elementalista Foundation — Sprint 2.9E-B

Mago (`mage`) and Elementalista (`elementalist`) are registered with
`playable: false` and `status: foundation`. They are hidden from normal class
selection and rejected by ClassSystem selection, combat-profile creation and
Gear Advisor compatibility. There are no playable spells, mana tuning, kit,
stat growth, rewards or combat-engine hooks. `ClassesData.resolve` recognizes
the foundation but throws for unknown classes instead of mapping them to Hunter.

## Additive selection migration

`ClassesData.normalizeSelection` is shared by ClassSystem and ProgressionStore.
The existing v2 key/schema is retained. A valid old selection receives only the
missing `builds.mage = elementalist`; classId and every previous selection are
preserved. Existing envelope fields and strategy keys remain untouched. The
migration writes once and is idempotent. No active activity/profile is rewritten.

Missing/invalid legacy selections, unknown identifiers, corrupt v2 data and
unknown versions are not inferred or overwritten: ClassSystem reports a storage
error and blocks writes. Fresh storage uses existing Hunter defaults plus the
inactive Mage selection. A failed additive write leaves original storage bytes
intact and preserves the valid selection in memory; the next load may retry.
Denied/absent storage remains an explicit error. Separate stores are not an
atomic transaction. No user save was supplied: v2 specimens were generated by
the actual ClassSystem at commit 372e1f6 using synthetic storage.

## Resonance contract v1

`elemental-resonance.js` is a pure browser/CommonJS module, inactive for every
existing combat profile. It never accesses DOM, storage, clocks or game rewards.

State: `{version: 1, nextOrder: 1, traces: []}`. Each trace contains
`element`, `expiresAt` and `order`. Elements have fixed tie priority:
**fire / water / earth / air** (Fuoco / Acqua / Terra / Aria).

- `create()` returns empty state.
- `apply(state, element, {now, duration})` returns a new state, refreshes that
  element to `now + duration`, and advances monotonic application order. At most
  one trace per element exists; expired traces are pruned on application.
- `active(state, now)` excludes traces at `expiresAt <= now` (exact boundary).
- `select(state, now)` returns two active traces sorted by earliest expiry,
  then fixed elemental priority, or null. Application order is retained for
  provenance but does not override the documented tie priority.
- `consume(state, now)` returns `{ok, pair, state}`. Success removes exactly the
  chosen pair, keeping the other traces intact. Failure returns `ok: false` with
  `reason: twoDistinctElementsRequired` and no state changes.

Inputs and outputs are independent copies. Consumption has no externally
observable intermediate mutation. This does **not** assert an atomic transaction
with mana/cooldowns/storage; those are outside this contract. Future integration
must validate and resolve the whole action before committing its encounter state.

`now` is non-negative finite seconds on one logical encounter clock. Duration is
mandatory, finite and positive, with no default balance value. Unknown versions,
invalid elements, duplicate traces and invalid timestamps/orders are rejected.
This module does not yet define Convergence effects or AUTO/custom conditions.

## Verification

`tests/mage-foundation-engine.cjs` covers original-system v2 specimens, additive
migration, reload idempotence, write/read denial, absent/corrupt/partial/future
storage, unchanged strategy/other keys, non-playable registration, exact prior
Vendicatore profile, four traces, all six pairs, refresh, expiry, tie ordering,
immutable consumption and serialization/reload. The specialization engine keeps
the 90,000 frozen legacy snapshots; browser regression verifies Mage is absent
from normal selection and the contract loads at 320/375/390/430 px.

Physical iPhone/Android validation is not claimed. Playable Elementalista,
equipment/reward progression and combat integration require a separate sprint.
